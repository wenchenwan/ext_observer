# 01 · 快速开始

> 目标：30 分钟内编译并运行示例，看到观测器输出的外力曲线，并知道怎样把它接进自己的代码。

---

## 1. 依赖

| 依赖 | 用途 | 必需？ |
|---|---|---|
| C++ 编译器（g++ / clang++，支持 C++11） | 编译库和示例 | ✅ |
| [Eigen 3](https://eigen.tuxfamily.org/) | 全部矩阵运算 | ✅ |
| make | 运行 `tests/`、`matlab/` 中的 Makefile | 推荐 |
| gnuplot | `make test` 等目标最后一步画图 | 可选 |
| MATLAB | 运行 `matlab/test.m`，横向对比各观测器 | 可选 |

**这个库没有其他第三方依赖**，也不需要单独编译，只需 include 头文件。

> ⚠️ **include 路径的写法**：源码使用 `#include <eigen3/Eigen/Geometry>` 和 `<eigen3/Eigen/Dense>`，也就是假设 Eigen 装在某个 include 根目录下的 `eigen3/` 子目录里（Linux 上通常是 `/usr/include/eigen3`）。
> 如果你的 Eigen 在别处（例如 Windows 上的 `C:/libs/eigen-3.4.0/Eigen`），要么把它放进一个名为 `eigen3` 的目录，要么用 `-I` 让 `<eigen3/Eigen/...>` 能被找到。

## 2. Linux 下运行示例

### 2.1 安装依赖

```bash
sudo apt install g++ make libeigen3-dev gnuplot
```

### 2.2 运行 M/C/G 版示例

```bash
cd tests
make test        # 编译 test.cpp → ./test → 生成 force.csv、input.csv → gnuplot 画图
```

预期结果：画出两条曲线（两个关节的 $\hat\tau_{ext}$）。它们在 0~1 s 和 2~3 s 接近 0，在 **1~2 s 内是约 +0.5 的方波**。

示例里默认启用的是**滑模观测器**。要换成别的观测器，编辑 [tests/test.cpp:8-14](../tests/test.cpp#L8-L14)，**只保留一行** `#include`：

```cpp
//#include "../lib/momentum_observer.h"
//#include "../lib/disturbance_observer.h"
#include "../lib/sliding_mode_observer.h"      // ← 当前启用
//#include "../lib/disturbance_kalman_filter.h"
//#include "../lib/filtered_dyn_observer.h"
//#include "../lib/filtered_range_observer.h"
//#include "../lib/disturbance_kalman_filter_exp.h"
```

> ⚠️ **切换前要先修一处代码**：动量观测器、卡尔曼观测器、精确离散卡尔曼观测器这三个分支里还残留旧类型名 `Vector`/`Matrix`，直接切换会编译失败。把它们改成 `VectorJ`/`MatrixJ` 即可，详见 [08 P5](08-已知问题与修复建议.md#p5-示例中未启用的分支无法编译)。
>
> 另外，精确离散卡尔曼观测器依赖 `kalman_filter_continous.cpp`，而 Makefile 的 `test` 目标已经把它加入编译，这一点无需操心。但它有一个**读取未初始化内存**的缺陷，见 [08 P1](08-已知问题与修复建议.md#p1-kalmanfiltercontinous-读取未初始化内存)。

## 3. MATLAB 封装

MATLAB 不能直接调用 C++ 类，所以 [matlab/](../matlab/) 用 `extern "C"` 函数把观测器包装成一个 C 接口的共享库，MATLAB 通过 `loadlibrary` / `calllib` 调用。

```bash
cd matlab
make            # 编译 observers.cpp + kalman_filter_continous.cpp → observers.so
make test       # 可选：用 C++ 程序 test_lib.cpp 调用 observers.so 做一次自检
```

然后在 MATLAB 中进入 `matlab/` 目录，运行：

```matlab
test            % 读取 input.csv，依次运行 6 个观测器并画图（精确离散卡尔曼观测器那段被注释掉了）
```

`input.csv` 就是 `tests/test.cpp` 生成的仿真数据（已核实：t = 1.5 s 时两列力矩都比理想值小 0.5）。

> 封装层的机器人模型是**写死的 2 连杆模型**（`static DoubleLink robot;`），关节数 `JOINT_NO = 2` 也是写死的。要用于真机，必须替换这两处，见 [07 §3](07-集成与调参指南.md#3-在-matlab-中使用真实机器人模型)。

## 4. Windows 注意事项

仓库只提供了 Linux Makefile。在 Windows 上：

| 问题 | 解决 |
|---|---|
| 没有 g++/make | 安装 MSYS2 并用 `pacman -S mingw-w64-x86_64-gcc mingw-w64-x86_64-eigen3 make`，或使用 WSL |
| `M_SQRT2` 未定义（[iir_filter.h:179](../lib/iir_filter.h#L179)） | MSVC 需要在包含 `<cmath>` **之前** `#define _USE_MATH_DEFINES`；MinGW 一般没问题 |
| `.so` 文件 | Windows 上共享库是 `.dll`：`g++ -shared -o observers.dll ...`，同时把 `test.m` 里的 `loadlibrary('observers.so', ...)` 改成 `.dll` |
| MATLAB `loadlibrary` 报找不到编译器 | MATLAB 需要配置一个受支持的 C 编译器（`mex -setup`） |
| `-Wl,-rpath` | 这是 Linux 链接选项，Windows 上去掉，把 dll 放到可执行文件同目录即可 |

**最简单的办法是 WSL**：在 WSL 的 Ubuntu 中，第 2 节的命令可以原样使用。

## 5. 最小集成示例

把观测器接进自己的程序，只需要三步。

### 第 1 步：实现机器人动力学接口

```cpp
#include "lib/external_observer.h"

class MyRobot : public RobotDynamics {
public:
  MatrixJ getM(VectorJ& q) override             { /* 返回 n×n 惯性矩阵 */ }
  MatrixJ getC(VectorJ& q, VectorJ& qd) override { /* 返回 n×n 科氏矩阵（必须是 Christoffel 形式！）*/ }
  VectorJ getG(VectorJ& q) override             { /* 返回 n×1 重力项 */ }
  VectorJ getFriction(VectorJ& qd) override     { /* 返回 n×1 摩擦力矩 */ }
  int jointNo() override                        { return 6; }
};
```

几个必须满足的**前置条件**（详见 [03 §3](03-架构与接口.md#3-接口契约实现-robotdynamics-时必须满足的条件)）：

1. `getC` 必须满足 $\dot M = C + C^T$，否则所有用到 $C^T\dot q$ 的观测器都会出错；
2. `getFriction` 返回的摩擦要满足 $\tau_{motor} = M\ddot q + C\dot q + G + \tau_f$ 这个符号约定；
3. 所有返回值的维度必须等于 `jointNo()`。

如果你只有 RNEA 形式的动力学（KDL、Pinocchio、RBDL 等），就继承 `RobotDynamicsRnea`，只实现 `rnea()`、`getFriction()`、`jointNo()` 三个函数，并**严格遵守 `g` 参数的约定**（见 [03 §3.4](03-架构与接口.md#34-rnea-的-g-参数约定)）。

### 第 2 步：创建观测器

```cpp
#include "lib/momentum_observer.h"

MyRobot robot;                        // 生命周期必须长于观测器
VectorJ k(6);
k << 30, 30, 30, 30, 30, 30;          // 要求 k·dt < 2，建议 k·dt ≤ 0.5
MomentumObserver observer(&robot, k);
```

### 第 3 步：在控制循环里调用

```cpp
VectorJ q(6), qd(6), tau(6);          // 必须是左值（接口参数是非 const 引用）
while (running) {
  read_state(q, qd, current);
  tau = drive_gains.cwiseProduct(current);   // 电流 → 力矩，由调用方负责
  double dt = now() - last;  last = now();
  if (dt <= 0) continue;                     // ⚠️ 防止 dt = 0（见 08 P3）
  VectorJ ext = observer.getExternalTorque(q, qd, tau, dt);
  if ((ext.cwiseAbs().array() > threshold.array()).any()) stop_robot();
}
```

需要记住的要点：

- **第一次调用总是返回 0**，它只用来初始化内部状态。
- 机器人暂停或重新上电后，调用 `observer.reset()`，下一次调用会重新初始化。
- `tau` 必须是**力矩**，不是电流。电流乘以驱动增益的换算由调用方完成，驱动增益可以用 `dynamic_calibration` 的 `estimate_drive_gains` 辨识。
- 同一个 `.cpp` 中可以 include 多个观测器头文件；但**同一个头文件不能被两个 `.cpp` 同时 include**，否则链接时会报重复定义，见 [03 §6](03-架构与接口.md#6-header-only-与-odr-约束)。
