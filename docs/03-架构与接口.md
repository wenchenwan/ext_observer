# 03 · 架构与接口

> 本章讲库的结构：有哪些类、它们如何协作、实现接口时**必须遵守哪些约定**、对象的生命周期，以及完整的 API 参考。
> 所有接口定义都在 [lib/external_observer.h](../lib/external_observer.h)（233 行），建议对照阅读。

## 1. 类层次

```
                 ┌──────────────────────────┐                    ┌─────────────────────────────┐
                 │   RobotDynamicsBase      │                    │   ExternalObserverBase      │
                 │  getFriction(qd)   [纯虚]│                    │  getExternalTorque(...)[纯虚]│
                 │  jointNo()         [纯虚]│                    │  reset()  type()             │
                 └───────┬──────────┬───────┘                    │  jointNo, objType, isRun     │
                         │          │                            └──────┬───────────────┬───────┘
          ┌──────────────┘          └───────────────┐                   │               │
┌─────────▼──────────┐                ┌─────────────▼────────────┐  ┌────▼─────────┐ ┌───▼──────────────┐
│ RobotDynamics      │                │ RobotDynamicsRnea        │  │ExternalObserver│ │ExternalObserverRnea│
│ getM(q)      [纯虚]│                │ rnea(q,qd,q2d,g=0) [纯虚]│  │ RobotDynamics* │ │ RobotDynamicsRnea* │
│ getC(q,qd)   [纯虚]│                │ getM(q)     [已实现]      │  │ dyn            │ │ dyn                │
│ getG(q)      [纯虚]│                │ tranCqd(q,qd) [已实现]    │  └────┬───────────┘ └───┬────────────────┘
└─────────▲──────────┘                │ setDelta(d)              │       │                 │
          │                           └─────────────▲────────────┘       │ 7 个观测器       │ 5 个观测器
          │ 用户实现                                 │ 用户实现           ▼                 ▼
   DoubleLink（测试）                         DoubleLinkRnea（测试）   MomentumObserver    MomentumObserverRnea
   你的机器人                                 你的机器人               DisturbanceObserver DisturbanceObserverRnea
                                                                      SlidingModeObserver SlidingModeObserverRnea
                                                                      DKalmanObserver     DKalmanObserverRnea
                                                                      DKalmanObserverExp  （无）
                                                                      FDynObserver        FDynObserverRnea
                                                                      FRangeObserver      （无）
```

这里有**两条平行的继承链**：

- **左边（机器人动力学）**：用户继承其中一个类，描述自己的机器人；
- **右边（观测器）**：每个观测器持有一个指向机器人对象的指针，通过它查询动力学量。

每个观测器都有 M/C/G 和 RNEA 两个版本（其中两个观测器只有 M/C/G 版），两个版本的**控制逻辑逐字相同**，只是获取动力学量的方式不同。

## 2. 两条动力学路线怎么选

| | `RobotDynamics`（M/C/G 路线） | `RobotDynamicsRnea`（RNEA 路线） |
|---|---|---|
| 用户需要实现 | `getM`、`getC`、`getG`、`getFriction`、`jointNo` | `rnea`、`getFriction`、`jointNo` |
| 适合场景 | 有解析的 $M, C, G$（例如 `dynamic_calibration` 生成的函数） | 使用 KDL、Pinocchio、RBDL 等动力学库 |
| $C$ 的要求 | **必须**是 Christoffel 形式（[§3.2](#32-getc-必须满足斜对称性)） | 无要求 |
| 每步计算量（6 轴） | 1 次 $M$ + 1 次 $C$ + 1 次 $G$ | 动量观测器等为 10 次 RNEA，扰动观测器为 7 次 RNEA |
| 可用观测器 | 7 个 | 5 个（没有 `DKalmanObserverExp`、`FRangeObserver`） |
| 精度 | 精确 | $C^T\dot q$ 由数值差分得到，有 $O(\delta)$ 截断误差 |

**建议**：有解析模型就用 M/C/G 路线，它更快、更准，观测器也更多。

## 3. 接口契约：实现 RobotDynamics 时必须满足的条件

下面这些约定**代码里没有任何检查**，违反了不会报错，只会给出错误的估计值。

### 3.1 维度一致

`getM` 返回 $n\times n$，`getC` 返回 $n\times n$，`getG`、`getFriction`、`rnea` 返回长度为 $n$ 的向量，$n$ = `jointNo()`。

- 观测器在**构造时**缓存 `jointNo`（[external_observer.h:196](../lib/external_observer.h#L196)），并按这个值分配内部向量。
- 传给观测器的增益向量（如动量观测器的 `k`）长度也必须是 $n$。
- **维度不匹配时**：Debug 模式下 Eigen 会触发断言；Release 模式（定义了 `NDEBUG`）下是**未定义行为**，可能越界读写。

### 3.2 getC() 必须满足斜对称性

`getC(q, qd)` 必须返回满足 $\dot M = C + C^T$ 的矩阵，即 Christoffel 形式。原因和反例见 [02 §4](02-理论基础.md#4-斜对称性)。

受影响的观测器：动量、滑模、两种卡尔曼、FDyn、FRange（它们都用 $C^T\dot q$）。

**不受影响**：扰动观测器，它只使用 $C\dot q$（[disturbance_observer.h:82](../lib/disturbance_observer.h#L82)）。

### 3.3 摩擦的符号约定

`getFriction(qd)` 返回的 $\tau_f$ 必须满足

$$
\tau = M\ddot q + C\dot q + G + \tau_f \quad(\text{无外力时})
$$

也就是说 $\tau_f$ 是**电机需要额外提供、用来克服摩擦的力矩**。对粘滞摩擦 $F_v\dot q$，$F_v > 0$ 时 $\tau_f$ 与 $\dot q$ 同号。

`dynamic_calibration` 中的模型 $\tau = Y\pi + Y_f\pi_f$ 正好采用这个约定，辨识出的 $[F_v, F_c, F_0]$ 可以直接使用，见 [07 §2.3](07-集成与调参指南.md#24-摩擦模型)。

> 库只支持**静态**摩擦模型（只依赖 $\dot q$），不支持 LuGre 这类带内部状态的动态摩擦。

### 3.4 rnea() 的 g 参数约定

```cpp
virtual VectorJ rnea(VectorJ& q, VectorJ& qd, VectorJ& q2d, double g = 0) = 0;
```

必须**精确**实现以下语义：

$$
\texttt{rnea}(q, \dot q, \ddot q, g) = M(q)\ddot q + C(q,\dot q)\dot q + G(q)\big|_{\text{重力加速度} = g}
$$

- **`g` 默认为 0**：不传 `g` 时**必须不含重力**；
- 观测器会把速度向量**放在加速度的位置**上调用（`rnea(q, 0, qd)` 用来得到 $M\dot q$），所以 `rnea` 必须对第三个参数是**线性**的，不能对加速度做任何限幅或滤波；
- **不能包含摩擦**，摩擦由 `getFriction` 单独提供；
- 使用 KDL / Pinocchio 时，要在每次调用前根据 `g` 设置重力向量（例如 `[0, 0, -g]`）。

观测器使用的调用组合（完整解释见 [04 §1](04-基础组件.md#1-rnea-辅助算法)）：

| 调用 | 结果 |
|---|---|
| `rnea(q, 0, qd)` | $M\dot q$（动量） |
| `rnea(q, 0, 0, GRAVITY)` | $G$ |
| `rnea(q, qd, 0)` | $C\dot q$ |
| `rnea(q, qd, 0, GRAVITY)` | $C\dot q + G$ |
| `rnea(q, 0, e_i)` | $M$ 的第 $i$ 列 |

### 3.5 参数必须是左值

所有接口参数都是**非 const 引用**（`VectorJ&`），所以不能直接传临时对象：

```cpp
obs.getExternalTorque(q, qd, K.cwiseProduct(i), dt);   // ❌ 编译错误：临时对象不能绑定到非 const 引用
VectorJ tau = K.cwiseProduct(i);
obs.getExternalTorque(q, qd, tau, dt);                 // ✅
```

观测器**不会修改**传入的 `q`、`qd`、`tau`（已逐个检查），所以不用担心数据被改写。

### 3.6 单位

库内部不做单位换算，所有量必须使用一致的 SI 单位：rad、rad/s、N·m、s。唯一的例外陷阱是 FDyn/FRange 的构造参数，名字写的是 Hz，实际单位是 **rad/s 和秒**，见 [08 P4](08-已知问题与修复建议.md#p4-cutoffhz--samphz-参数名与实际单位不符)。

## 4. 观测器的生命周期

### 4.1 状态机

所有观测器都继承同一个布尔标志 `isRun`（[external_observer.h:177](../lib/external_observer.h#L177)）：

```
          构造                        第一次 getExternalTorque()                 之后每次调用
  ┌────────────────┐           ┌──────────────────────────────┐          ┌────────────────────────┐
  │ isRun = false  │ ────────▶ │ 用当前测量初始化内部状态       │ ───────▶ │ 正常更新并返回 τ̂_ext   │
  │ 内部状态未初始化│           │ isRun = true，返回 0          │          │                        │
  └────────────────┘           └──────────────────────────────┘          └───────────┬────────────┘
          ▲                                                                           │
          └───────────────────────────── reset()：isRun = false ◀─────────────────────┘
```

**不变量**：✅ 已对每个观测器逐一追踪首次调用路径，**第一次调用一定返回零向量**。

### 4.2 各观测器的内部状态与初始化

| 观测器 | 持久状态 | 首次调用时的初始化 | 为什么这样初始化 |
|---|---|---|---|
| 动量 | `sum`（积分 + $p_0$）、`r`、`tprev` | `sum = p`，`r = 0` | 让 $p - \int - p_0 = 0$ |
| 扰动 | `z` | `z = -Y·q̇` | 让 $\hat\tau = Yq̇ + z = 0$ |
| 滑模 | `p_hat`、`sigma` | `p_hat = p`，`sigma = 0` | 动量误差为 0，外力估计为 0 |
| 卡尔曼（两种） | 滤波器的 `X`、`P` | `X = [p; 0]`，`P = 0` | 动量取实测值，扰动取 0 |
| FDyn / FRange | 两个滤波器的 `x1`、`y1` | 设为对应输入的**稳态**值 | 避免启动时出现尖峰 |

### 4.3 什么时候调用 reset()

- 机器人**重新上电**或**长时间暂停**后（积分器和滤波器中的旧状态已经不再有意义）；
- **切换了负载**或**修改了模型参数**之后；
- `dt` 出现异常（例如通信中断后恢复）之后。

`reset()` 只是把 `isRun` 置为 false，**不会清零**任何数值；真正的重新初始化发生在下一次 `getExternalTorque()` 调用中。

`settings(...)` 可以在运行中随时修改参数，**不会**重置状态。

## 5. 所有权、内存与线程安全

### 5.1 机器人对象的所有权

```cpp
RobotDynamics *dyn;   // external_observer.h:203，裸指针，不拥有
```

观测器**不会** `delete` 机器人对象。调用方必须保证机器人对象的生命周期**长于**所有使用它的观测器。多个观测器可以共享同一个机器人对象，`matlab/observers.cpp` 就是这样做的：`static DoubleLink robot;` 被所有观测器共享。

### 5.2 卡尔曼观测器拥有滤波器

三个卡尔曼观测器在构造函数中 `new` 了一个滤波器，并在析构函数中 `delete`。它们**没有禁用拷贝**，拷贝一个对象会导致 double-free，见 [08 P10](08-已知问题与修复建议.md#p10-卡尔曼观测器可以被拷贝导致-double-free)。

**建议**：总是通过指针或引用传递观测器，不要按值传递或拷贝。

### 5.3 堆分配

代码中大量使用成员变量作为临时量，注释写着 “avoid memory reallocation”。但接口本身按值返回 `MatrixJ`/`VectorJ`，所以**每次调用仍然会有若干次堆分配**：

- `getM()`、`getC()`、`getG()` 的返回值；
- 表达式 `dyn->getM(q) * qd` 的中间结果；
- `getExternalTorque()` 的返回值。

对 1 kHz、6 轴的控制循环，这通常不成问题；但**在硬实时系统中（例如 Xenomai、PREEMPT_RT 的实时线程）**，堆分配可能引起不可预测的延迟。改进方法见 [07 §5](07-集成与调参指南.md#5-实时性考虑)。

### 5.4 线程安全

**库不是线程安全的**：

- 每个观测器都有内部状态，**不能在多个线程中同时调用同一个观测器**；
- `RobotDynamicsRnea` 把临时量存在成员变量里（`_qext`、`_p0`、`_zero`、`_sum`、`_M`，[external_observer.h:133-134](../lib/external_observer.h#L133-L134)），所以**不同线程中的观测器也不能共享同一个 RNEA 机器人对象**；
- 如果你自己实现的 `RobotDynamics` 也用成员变量缓存结果（例如测试中的 `DoubleLink` 就把 `M`、`C`、`G` 存为成员），同样不能跨线程共享。

**做法**：每个线程使用各自的机器人对象和观测器对象。

## 6. header-only 与 ODR 约束

除了 `robot_dynamics_rnea.cpp` 和 `kalman_filter_continous.cpp`，其余代码（包括成员函数的实现）都写在头文件里，而且这些函数**既没有标记 `inline`，也不是模板**。例如：

```cpp
// momentum_observer.h:70，定义在类外，没有 inline
VectorJ MomentumObserver::getExternalTorque(VectorJ& q, VectorJ& qd, VectorJ& tau, double dt) { ... }
```

根据 C++ 的**单一定义规则**（One Definition Rule，ODR），这样的函数只能在整个程序中定义一次。所以：

| 做法 | 结果 |
|---|---|
| 一个 `.cpp` include 多个不同的观测器头文件 | ✅ 可以（`matlab/observers.cpp` 就 include 了全部 7 个） |
| 两个 `.cpp` include **同一个**观测器头文件 | ❌ 链接错误：multiple definition |
| 两个 `.cpp` 都 include `iir_filter.h` 或 `kalman_filter.h`（间接也算） | ❌ 同上 |

**需要链接的源文件**：

- 使用 `RobotDynamicsRnea` 时，要编译并链接 [lib/robot_dynamics_rnea.cpp](../lib/robot_dynamics_rnea.cpp)；
- 使用 `DKalmanObserverExp` 时，要编译并链接 [lib/kalman_filter_continous.cpp](../lib/kalman_filter_continous.cpp)。

**如果需要在多个编译单元中使用**，最简单的修复是给头文件中所有类外定义的函数加上 `inline`，见 [08 P6](08-已知问题与修复建议.md#p6-头文件中的函数没有-inline多文件项目链接失败)。

## 7. 观测器类型 ID

每个观测器在构造时通过基类记录一个整数 ID（`objType`），可以用 `type()` 查询：

| ID | 类 | ID | 类 |
|---|---|---|---|
| 1 | `DKalmanObserver` | 21 | `DKalmanObserverRnea` |
| 2 | `FDynObserver` | 22 | `FDynObserverRnea` |
| 3 | `SlidingModeObserver` | 23 | `SlidingModeObserverRnea` |
| 4 | `DisturbanceObserver` | 24 | `DisturbanceObserverRnea` |
| 5 | `MomentumObserver` | 25 | `MomentumObserverRnea` |
| 6 | `FRangeObserver` | — | — |
| 7 | `DKalmanObserverExp` | — | — |

规律：RNEA 版的 ID = M/C/G 版的 ID + 20。

这些 ID 只在 C 封装层（`matlab/observers.cpp`）中使用：C 接口只能传递整数句柄，丢失了类型信息，所以 `config*()` 函数用 `type()` 检查句柄对应的观测器类型是否正确。

## 8. API 参考

### 8.1 公共方法（所有观测器）

| 方法 | 说明 |
|---|---|
| `VectorJ getExternalTorque(VectorJ& q, VectorJ& qd, VectorJ& tau, double dt)` | 主方法。`dt` 是距上一次调用的时间（秒），**必须 > 0**（首次调用除外）。返回 $\hat\tau_{ext}$ |
| `void reset()` | 下一次调用时重新初始化 |
| `int type() const` | 返回类型 ID |

### 8.2 各观测器的构造函数与参数

| 类 | 构造函数 | 参数说明 | `settings()` |
|---|---|---|---|
| `MomentumObserver` | `(RobotDynamics*, VectorJ& k)` | `k`：每个关节的增益，单位 1/s，要求 $k_i\Delta t < 2$ | `settings(k)` |
| `DisturbanceObserver` | `(RobotDynamics*, double sigma, double xeta, double beta)` | 三个参数合成为 $k = \frac12(\xi + 2\beta\sigma)$，$Y = kI$ | `settings(sigma, xeta, beta)` |
| `SlidingModeObserver` | `(RobotDynamics*, VectorJ& t1, VectorJ& s1, VectorJ& t2, VectorJ& s2)` | 每个关节的 $T_1, S_1, T_2, S_2$；建议 $T_i = 2\sqrt{S_i}$ | `settings(t1, s1, t2, s2)` |
| `DKalmanObserver` | `(RobotDynamics*, MatrixJ& s, MatrixJ& h, MatrixJ& q, MatrixJ& r)` | $S, H$：$n\times n$；$Q$：$2n\times 2n$（每步）；$R$：$n\times n$（动量噪声） | `settings(Q, R)`，只能改噪声 |
| `DKalmanObserverExp` | 同上 | $Q$：$2n\times 2n$（**每秒**）；$R$：$n\times n$（**速度层面**的噪声谱密度） | `settings(Q, R)` |
| `FDynObserver` | `(RobotDynamics*, double cutOffHz, double sampHz)` | ⚠️ 实际是 **截止频率 rad/s** 和 **采样周期 s** | `settings(cutOff, sampTime)` |
| `FRangeObserver` | `(RobotDynamics*, double cutOffHz, double sampHz, double k)` | 同上，外加模型相对误差 $k$（如 ±0.1） | `settings(cutOff, sampTime, k)` |

RNEA 版本的构造函数参数与对应的 M/C/G 版完全相同，只是第一个参数换成 `RobotDynamicsRnea*`。

### 8.3 RobotDynamicsRnea 的额外方法

| 方法 | 说明 |
|---|---|
| `MatrixJ getM(VectorJ& q)` | 调用 $n$ 次 `rnea` 拼出 $M$ |
| `VectorJ tranCqd(VectorJ& q, VectorJ& qd)` | 调用 $n+2$ 次 `rnea`，用数值差分得到 $C^T\dot q$ |
| `void setDelta(double d)` | 设置差分步长，默认 $10^{-7}$ rad |

| 名称 | 定义 | 位置 |
|---|---|---|
| `GRAVITY` | `const double GRAVITY = 9.81;` | [external_observer.h:17](../lib/external_observer.h#L17) |
| `MatrixJ` | `Eigen::MatrixXd`（动态大小） | [external_observer.h:22](../lib/external_observer.h#L22) |
| `VectorJ` | `Eigen::VectorXd`（动态大小） | [external_observer.h:23](../lib/external_observer.h#L23) |
