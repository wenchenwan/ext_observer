## 2. 对接 dynamic_calibration

### 2.1 三种实现方式

| 方式 | 需要的参数 | 需要的生成代码 | 可用观测器 | 推荐度 |
|---|---|---|---|---|
| **A. 基回归矩阵实现 `rnea()`** | $\pi_b$（OLS 或 PC-OLS 都可以） | `standard_regressor_UR10E`（59 KB） | 5 个 RNEA 版 | ⭐ **推荐** |
| B. 解析 M/C/G | $\pi_s$（只有 PC-OLS 给出）+ 转子惯量 | `M_mtrx_fcn`、`C_mtrx_fcn`（**3.4 MB**）、`G_vctr_fcn` | 全部 7 个 | 可行，但代码量大 |
| C. 动力学库（Pinocchio、KDL） | $\pi_s$ 写回 URDF + 转子惯量 | 无 | 5 个 RNEA 版 | 已有动力学库时推荐 |

### 2.2 方式 A：用基回归矩阵实现 rnea()（推荐）

**原理**：`dynamic_calibration` 已经得到

$$
\tau_{rb} = Y(q,\dot q,\ddot q)\,E_1\,\pi_b
$$

它对 $\ddot q$ 是线性的，不含摩擦，重力加速度固定为 9.81（[generate_rb_regressor.m:22](../../dynamic_calibration/dynamics/generate_rb_regressor.m#L22)），这些正是 `rnea()` 需要的性质（[03 §3.4](03-架构与接口.md#34-rnea-的-g-参数约定)）。唯一的问题是 `rnea()` 默认要求**不含重力**，而回归矩阵总是含重力。可以这样解决：

$$
\texttt{rnea}(q,\dot q,\ddot q,g) =
\begin{cases}
Y(q,\dot q,\ddot q)E_1\pi_b, & g = 9.81\\[2pt]
Y(q,\dot q,\ddot q)E_1\pi_b - Y(q,0,0)E_1\pi_b, & g = 0
\end{cases}
$$

因为 $Y(q,0,0)E_1\pi_b = G(q)$。

**优点**：

- 只需要基参数 $\pi_b$，OLS 的结果也能用，不需要从 $\pi_b$ 重建标准参数；
- 自动包含转子惯量（使用 `regressorWithMotorDynamics` 的 66 列形式即可）；
- 不依赖 $C$ 的具体形式（RNEA 路线天然不需要 Christoffel 形式，[04 §1.4](04-基础组件.md#为什么-rnea-路线不依赖-christoffel-形式)）。

**实现步骤**：

1. 在 MATLAB 中用 MATLAB Coder（`codegen`）把 `standard_regressor_UR10E` 生成为 C 代码；如果没有 Coder，也可以对 `generate_rb_regressor.m` 中的符号表达式 `Y_f` 调用 `ccode()`；
2. 导出以下数据，写成 C++ 常量或配置文件：
   - `E1 = baseQR.permutationMatrix(:, 1:40)`（66×40）；
   - `sol.pi_b`（40×1）；
   - **注意**：`E1` 与 `pi_b` 必须来自**同一次** `base_params_qr` 运行（见 [dynamic_calibration 文档 §9.6](../../dynamic_calibration/CODE_WALKTHROUGH.md#96-baseqr-每次运行都会重新计算)）；
3. 实现：

```cpp
class UR10eRegressorRnea : public RobotDynamicsRnea {
public:
  VectorJ rnea(VectorJ& q, VectorJ& qd, VectorJ& q2d, double g = 0) override {
    VectorJ tau = Yb(q, qd, q2d) * pi_b;          // Yb = [Y_rb, diag(q2d) 交错插入] * E1，6×40
    if (g == 0) {
      VectorJ z = VectorJ::Zero(6);
      tau -= Yb(q, z, z) * pi_b;                  // 减去重力项 G(q)
    }
    return tau;
  }
  VectorJ getFriction(VectorJ& qd) override { /* 见 §2.4 */ }
  int jointNo() override { return 6; }
private:
  MatrixJ Yb(VectorJ& q, VectorJ& qd, VectorJ& q2d);   // 调用生成的回归矩阵代码
  VectorJ pi_b;                                        // 40×1
};
```

> ⚠️ 这个实现只支持 `g = 0` 和 `g = 9.81` 两种情况（库中只使用这两个值）。如果需要其他重力值，就必须修改 `generate_rb_regressor.m` 中的重力定义并重新生成。

计算量：`tranCqd` 需要 $n+2 = 8$ 次 `rnea()`，每次 `rnea()` 在 $g=0$ 时要算 2 次回归矩阵。如果这成为瓶颈，可以单独提供一个带重力的缓存。

### 2.3 方式 B：解析 M/C/G

`dynamic_calibration` 中的 `M_mtrx_fcn(q, pi)`、`C_mtrx_fcn(q, qd, pi)`、`G_vctr_fcn(q, pi)` 使用 **60 个**刚体标准参数（每个连杆 10 个，不含转子惯量）。

需要注意：

| 问题 | 处理 |
|---|---|
| 标准参数 $\pi_s$ 只有 PC-OLS 方法给出（`sol.pi_s`，66 个，每个连杆 11 个） | 从中去掉每个连杆的第 11 个元素（转子惯量），得到 60 个参数 |
| 转子惯量 `im` | 加到惯性矩阵的对角线上：$M_{total} = M_{rb}(q) + \mathrm{diag}(im_1,\ldots,im_6)$。它是常数，所以不影响 $C$ 和 $G$ |
| $C$ 的形式 | `generate_rb_dynamics.m` 用 Christoffel 符号生成 $C$ ✅，满足观测器的要求 |
| `C_mtrx_fcn.m` 有 3.4 MB | 生成的 C 代码同样巨大，编译慢。可以只生成 $C^T\dot q$ 这一个向量，而不是整个矩阵 |

仓库自带的 [UR10E_parameters.txt](../../dynamic_calibration/UR10E_parameters.txt) 给出了一组已辨识的结果，布局正好符合方式 B：`pi_rgd`（60 个）、`pi_drvs`（6 个转子惯量）、`pi_frcn`（18 个）、`drvGains`（6 个）。

### 2.4 摩擦模型

`dynamic_calibration` 辨识的摩擦模型（每个关节 3 个参数，`pi_fr` 按 `[Fv, Fc, F0]` 依次排列）：

$$
\tau_{f,i} = F_{v,i}\,\dot q_i + F_{c,i}\,\mathrm{sign}(\dot q_i) + F_{0,i}
$$

符号约定与观测器一致（[03 §3.3](03-架构与接口.md#33-摩擦的符号约定)），可以直接使用：

```cpp
VectorJ getFriction(VectorJ& qd) override {
  VectorJ f(6);
  for (int i = 0; i < 6; i++) {
    double Fv = pi_fr(3*i), Fc = pi_fr(3*i+1), F0 = pi_fr(3*i+2);
    f(i) = Fv*qd(i) + Fc*std::tanh(qd(i)/eps) + F0;   // 用 tanh 平滑 sign，eps 约 0.01 rad/s
  }
  return f;
}
```

**为什么要平滑 sign**：速度过零时，$\mathrm{sign}(\dot q)$ 在 $\pm F_c$ 之间跳变，而真实摩擦是连续过渡的（静摩擦区）。直接使用 sign 会在每次换向时产生一个 $2F_c$ 的虚假外力尖峰。以 UR10E_parameters.txt 为例，关节 1 的 $F_c \approx 12.5$ N·m，这个尖峰足以触发误报警。

### 2.5 驱动增益

UR10e 只能读到电流，需要换算为力矩：$\tau_i = K_i\,i_i$。

- $K$ 来自 `estimate_drive_gains`（[UR10E_parameters.txt](../../dynamic_calibration/UR10E_parameters.txt) 中 `drvGains = [10.0, 10.70, 8.46, 9.00, 9.48, 10.12]`）；
- 注意 `dynamic_calibration` 文档指出：$K_1 = 10.0$ 正好等于辨识时设置的下界，说明它是由约束决定的，而不是由数据决定的，关节 1 的力矩估计因此可能有系统误差；
- 这一步由调用方完成，观测器不负责换算（[matlab/test.m:37](../matlab/test.m#L37) 中的 `K.*cur(i,:)`）。

### 2.6 一致性检查清单

在上线之前，逐项确认两个项目使用了**相同的约定**：

- [ ] **关节顺序**和**零位**：`dynamic_calibration` 使用 URDF（`ur10e.urdf`）中的关节定义，与 UR 控制器一致；
- [ ] **速度来源**：辨识时用的是滤波后的 $\dot q$（`qd_fltrd`），在线使用时的速度噪声水平可能不同；
- [ ] **重力方向**：两边都是 $+z$ 向上、$g = 9.81$；
- [ ] **电流符号**：电流为正时力矩也为正；
- [ ] **单位**：rad、rad/s、N·m、A；
- [ ] **离线复现**：用 `dataset_ur10e/validation_data/` 中的数据跑一遍观测器，在无碰撞的情况下，输出应该接近 0（残余量就是模型误差）；
- [ ] **碰撞复现**：用 `dataset_ur10e/collision/` 中的两个推动实验（约 1730 行，采样周期约 0.01 s），确认能检测到碰撞。

## 4. 调参流程

### 4.1 通用步骤

1. **确定控制周期** $\Delta t$。UR e 系列通过 RTDE 最高可以 500 Hz 获取数据（$\Delta t = 2$ ms）；`dynamic_calibration` 的数据集是约 100 Hz。
2. **选择观测器**（[05 §8.2](05-观测器详解.md#82-该选哪个)），先用动量观测器或 FDyn。
3. **确定带宽**：碰撞检测一般要求在 20~50 ms 内反应，对应带宽 $K_O$ 或 $\omega$ 为 20~50 rad/s。同时要满足：
   - 动量观测器：$K_O\Delta t \le 0.5$；
   - 滑模观测器：$T_2 > (50S_1 + S_2)\Delta t$。
4. **无碰撞运行**：让机器人跑覆盖工作空间的典型轨迹（包括高速段和加减速段），记录 $\hat\tau_{ext}$。此时的输出全部是模型误差和噪声。
5. **设定阈值**（§4.3）。
6. **碰撞测试**：在不同位形、速度下进行实际推碰，确认检测率和响应时间。

### 4.2 各观测器的起始参数

以 $\Delta t = 2$ ms（500 Hz）为例：

| 观测器 | 起始参数 | 约束 |
|---|---|---|
| 动量 | $K_O = 30$（每个关节） | $K_O \le 0.5/\Delta t = 250$ |
| FDyn | $\omega = 30$ rad/s | — |
| 扰动 | `sigma=1, xeta=0, beta` = $30\,\lambda_{max}(M)$ | — |
| 滑模 | $S_2 = 900$（$\sqrt{S_2}=30$ rad/s），$S_1$ 从 0 开始逐渐加大 | $T_2 > (50S_1 + S_2)\Delta t$ |
| 卡尔曼（欧拉） | $Q_p = 10^{-4}$、$Q_\omega = 10^{-1}$、$R = 10^{-2}$，再根据响应调 $Q_\omega/R$ | $Q, R$ 是每步的值，改变 $\Delta t$ 后要换算 |

这些只是起点，最终要根据 §4.1 第 4 步的实测数据调整。

### 4.3 碰撞判据

| 判据 | 公式 | 优点 | 缺点 |
|---|---|---|---|
| 固定阈值 | $\lvert\hat\tau_{ext,i}\rvert > \theta_i$ | 简单 | 高速时模型误差大，易误报；静止时又过于保守 |
| 自适应阈值（FRange） | $\lvert\hat\tau_{ext,i}\rvert > \lvert r_i^{(k)}\rvert + \theta_{0,i}$ | 阈值随工况变化 | 多一个观测器，需要估计 $k$ |
| 加去抖 | 连续 $N$ 个周期超过阈值才报警 | 抑制单点噪声 | 增加 $N\Delta t$ 的延迟 |

**固定阈值的确定方法**：取无碰撞运行中 $|\hat\tau_{ext,i}|$ 的最大值，乘以 1.2~1.5 的安全系数，每个关节单独设定。

**自适应阈值**：见 [05 §7.4](05-观测器详解.md#74-用法自适应阈值)。$\theta_{0,i}$ 可以取静止时 $|\hat\tau_{ext,i}|$ 的最大值。

## 5. 实时性考虑

### 5.1 计算量

每步主要计算量（$n = 6$）：

| 路线 | 主要开销 |
|---|---|
| M/C/G 版动量观测器 | 生成的 $M$、$C$、$G$ 函数各 1 次 + 若干 6 维向量运算 |
| RNEA 版动量观测器 | 10 次 RNEA |
| 扰动观测器 | 另加 2 次 6×6 求逆 |
| 卡尔曼观测器 | 12×12 矩阵乘法若干次 + 1 次 6×6 求逆 |
| 精确离散卡尔曼 | 另加 2 次矩阵指数（18×18 和 24×24，各 5 次矩阵乘法） |

对现代 CPU 来说，所有观测器在 1 kHz 下都没有压力，瓶颈通常在动力学函数本身（特别是 3.4 MB 的 `C_mtrx_fcn`）。

### 5.2 动态内存分配

库使用动态大小的 `Eigen::MatrixXd`，并且接口按值返回矩阵，每次调用都会有若干次堆分配（[03 §5.3](03-架构与接口.md#53-堆分配)）。在硬实时线程中，改进方法有：

1. 把 `MatrixJ`/`VectorJ` 改为固定大小类型，例如 `Eigen::Matrix<double, 6, 6>`，所有运算都在栈上完成；
2. 把接口改为输出参数形式，例如 `void getM(const VectorJ& q, MatrixJ& out)`；
3. 把 `inverse()` 改为 `ldlt().solve()` 或 `lu().solve()`；
4. 在控制循环外预热一次（先调用一次 `getExternalTorque`），让 Eigen 完成首次分配。

### 5.3 dt 的处理

- **必须保证 `dt > 0`**，否则 FDyn/FRange 会永久输出 NaN（[08 P3](08-已知问题与修复建议.md#p3-dt--0-导致-nan-永久污染)）；
- 如果通信中断导致 `dt` 远大于正常值，建议调用 `reset()` 而不是直接使用这个 `dt`；
- 使用驱动器提供的时间戳计算 `dt`，而不是本机时钟，这样更准确。

## 6. 添加一个新观测器

以添加一个名为 `MyObserver` 的观测器为例：

**第 1 步：选择 ID**。在头文件中定义一个未被占用的 ID（现有 1~7、21~25），RNEA 版按惯例加 20：

```cpp
#define ID_MyObserver 8
```

**第 2 步：编写类**，遵循现有的模式：

```cpp
#include "external_observer.h"

class MyObserver final : public ExternalObserver {
public:
  MyObserver(RobotDynamics *rd, /* 参数 */)
    : ExternalObserver(rd, ID_MyObserver)
    , state(VectorJ::Zero(jointNo))      // jointNo 已由基类构造函数设置，可以直接用
  { settings(/* 参数 */); }

  VectorJ getExternalTorque(VectorJ& q, VectorJ& qd, VectorJ& tau, double dt) override {
    if (isRun) {
      /* 正常更新 */
    } else {
      /* 用当前测量初始化，保证首次返回 0 */
      isRun = true;
    }
    return /* τ̂_ext */;
  }

  void settings(/* 参数 */) { /* ... */ }

private:
  VectorJ state;
};
```

**第 3 步：注意事项**

- 用 `tau - dyn->getFriction(qd)` 扣除摩擦；
- 如果用到 $C^T\dot q$，在文档中注明需要 Christoffel 形式的 $C$；
- 如果持有动态分配的资源，使用 `std::unique_ptr` 而不是裸指针（避免 [08 P10](08-已知问题与修复建议.md#p10-卡尔曼观测器可以被拷贝导致-double-free) 的问题）；
- 如果头文件会被多个 `.cpp` 包含，给类外定义的函数加上 `inline`；
- 检查 `dt = 0` 时的行为。

**第 4 步：RNEA 版本**。复制一份，把基类改为 `ExternalObserverRnea`，并按下表替换动力学调用：

| M/C/G 版 | RNEA 版 |
|---|---|
| `dyn->getM(q) * qd` | `dyn->rnea(q, zero, qd)` |
| `dyn->getG(q)` | `dyn->rnea(q, zero, zero, GRAVITY)` |
| `dyn->getC(q, qd).transpose() * qd` | `dyn->tranCqd(q, qd)` |
| `dyn->getC(q, qd) * qd + dyn->getG(q)` | `dyn->rnea(q, qd, zero, GRAVITY)` |
| `dyn->getM(q)` | `dyn->getM(q)`（基类已实现） |

**第 5 步：注册到 MATLAB 封装**（如果需要）：

1. 在 [matlab/observers.h](../matlab/observers.h) 中声明 `configMyObserver(...)`；
2. 在 [matlab/observers.cpp](../matlab/observers.cpp) 中 include 头文件，按现有模式实现 `configMyObserver`；
3. ⚠️ **在 `freeAll()` 的 `switch` 中加上新的 `case`**，否则会**静默内存泄漏**。更好的做法是按 [08 P7](08-已知问题与修复建议.md#p7-freeall-的-switch-多余且容易漏改) 的建议把 `switch` 简化为 `delete observer[i];`。

**第 6 步：测试**。在 `tests/test.cpp` 中按 include guard 模式加入配置和调用；并按 [06 §6](06-测试与验证.md#6-建议补充的测试) 补充带噪声和模型误差的测试。

## 7. ROS 集成

仓库 README 提到：

- `ros_examples` 分支中有 ROS 集成示例；
- [ext_observer_ros](https://github.com/mikhel1984/ext_observer_ros) 是一个 ROS2 节点，用 URDF 描述运动学树，用 Orocos KDL 计算动力学，也就是本章 §2.1 的方式 C。

使用 KDL 时，实现 `RobotDynamicsRnea::rnea()` 的要点：

- 用 `KDL::ChainIdSolver_RNE` 计算逆动力学，**每次调用时根据参数 `g` 设置重力向量**（`g = 0` 时为零向量）；
- 外部力 `f_ext` 设为 0；
- 不要在 `rnea()` 中加入摩擦；
- 如果要使用辨识出的参数，需要把 $\pi_s$ 转换回 URDF 的惯性表示：质心 $r = h/m$，质心处的惯性张量 $I_c = I_o + m\,S(r)^2$（$S(\cdot)$ 为反对称矩阵，即 `dynamic_calibration` 中 `parse_urdf.m` 所做换算的逆运算）。转子惯量不在 URDF 中，需要另外加到 $M$ 的对角线上（Pinocchio 中可以使用 `model.armature`）。
